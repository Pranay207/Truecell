# Build verification — Truecell 2.0 working source

Core QA was rerun locally on Windows with 64-bit Python 3.11.9 on 21 October 2026. Direct and resolved dependencies are pinned. These are development checks, not hidden-document accuracy claims.

- **260 Python tests passed** in the development environment. Ruff lint and formatting checks passed, and recorded-output verification passed all 23 source-bound fixtures. See [QA findings and verification](QA_REPORT.md) for the reproduced issues and fixes.
- The **Windows x64 portable application** was rebuilt from the current source as a 316.68 MiB PyInstaller one-folder bundle and a 152.50 MiB ZIP (SHA-256 `7e1d86651f10a84e9570c14fb4e612b3197d827cb6e450529e508d1f68ed1278`). Its packaged EXE passed health and React UI checks, exact native-PDF extraction, bundled RapidOCR extraction with external Tesseract disabled, Excel/audit downloads, launch from a path containing spaces, and workspace persistence after restart.
- **15 frontend tests passed**, followed by strict TypeScript checks and an optimized Vite production build. Coverage includes extracted-row search, original-index preservation, OCR-language upload options, snapshot-safe review requests and recovery behavior. The built React interface is included in `frontend/dist`, so normal use does not require Node.js. Responsive rules cover desktop, tablet and narrow mobile widths.
- A restarted FastAPI server returned HTTP 200 for the health endpoint, React landing page, hashed JavaScript/CSS assets, source-page PNG, evidence workbook and audit JSON. The optional LAN launch was also reached through its exact `192.168.0.3` private-network URL while preserving loopback access. The live bank sample produced one 19-row × 6-column table. Its disposable proposal preview changed the reported finding count from 4 to 2 and failed equation checks from 2 to 0 while the saved value remained `1081.00` and the snapshot fingerprint stayed unchanged. The Challenge rail caught 22 of 24 controlled edits in that run; this is validator sensitivity, not OCR accuracy.
- **23/23 recorded dummy development outputs passed** source-hash and exact-score verification. The raster-only five-page continuation fixture recovered its 33 rows × 12 columns, removed four repeated headers and joined both page-break split rows after Tesseract/RapidOCR cross-checking. The new disclosed 13-page equivalent recovered four 14-column tables, 78 rows and 1,092/1,092 data cells exactly, with 1,148/1,148 non-empty headers/data cells carrying source boxes. The suite also covers an 18-column borderless table, explicitly ruled vertical group spans with nested line items, sparse schedules, carry-forwards, a sideways scan, a no-table letter, degradation cases, and 50 pages/800 rows. See `ACCURACY_REPORT.md` and `THIRTEEN_PAGE_EQUIVALENT.md`.
- **5/5 scan cases passed with Tesseract excluded**: inventory, blur/noise, skew, perspective photo and sideways invoice. This isolates the bundled RapidOCR path through an engine-selection override; it is not OS-level network isolation or a cross-platform execution test. See `PORTABLE_OCR.json` for actual results and timing.
- The cached public audit passed its disclosed scope: 35/35 fuel-table cells and seven headers; 48/48 selected census cells, all 16 headers and both table shapes; zero invented tables for the W3C control; and 126/126 cells plus 14/14 flattened headers across two public Unicode tables. The other 464 census data cells were not independently checked. These are known development inputs, not blind evaluation.
- The recorded Excel readback audit predates the vertical-span case and checked the original **20 workbooks**, their table row counts and headers, all 20 source SHA-256 bindings and 1,067 identifier cells. Identifiers remained explicit strings. No formula-type cells occurred in any worksheet. Those 20 exports contain 13,225 data-cell positions in total; this is a coverage count, not an independent accuracy measurement.
- FastAPI tests cover upload, source inspection, edits, immutable baselines, complete paginated review, per-item acknowledgements, honest partial/failed/quality states, Draft versus Reviewed Excel gates, CSV/audit downloads, workspace deletion and reprocessing boundaries. Frontend unit tests cover API requests and display formatting. The packaged server served the rebuilt React UI, but browser surfaces were unavailable for a new live screenshot pass in this automation session; native Excel rendering was also not performed.
- The offline environment check succeeded and verified the bundled English model checksum. No API credentials or live vision-provider calls were used. Python 3.10/3.12 and Linux/macOS are supported targets with CI configuration, not locally executed platform results.

The upgrade adds per-page quality/content/script profiling, damaged-text OCR escalation, optional multilingual Tesseract routing, evidence-ranked cross-checks, semantic column roles, repeated-header consensus, full-width-title separation, stronger structural validation, complete evidence accounting, a paginated exception queue, honest result states, quality-gated Reviewed Excel, CSV delivery, Docker Compose and a two-stage blind-evaluation harness. Regression checks include a disclosed 13-page/four-table equivalent and keep every repair or human edit explicit. Heuristics still require source review.

Known limitations include handwriting, uninstalled OCR language packs, broken glyph maps, severe cropping and imperfect OCR descriptions on some external scans. Explicitly ruled vertical group spans in native-PDF body rows are supported conservatively; OCR/unruled spans and arbitrary multi-axis nested merges remain ambiguous. Mathematical agreement and recognition confidence are not correctness guarantees. Human edits and proposals remain explicit; the benchmark never auto-applies arithmetic repairs. The default server binds to loopback. Optional `--lan` access is limited to the detected RFC 1918 host and private-network clients and can depend on the computer's firewall setting.

The current source tree contains the launchers, engine, bundled frontend, OCR model, 23 dummy input/truth/output sets, reports, tests, portable build instructions and licence notices. Generated environments, dependency caches, temporary files, runtime workspaces, local build folders, credentials and personal data remain ignored. The portable ZIP is a local release artifact and is not committed to Git.

`docker compose config` passed. A Linux container image was not built locally because Docker Desktop's Linux engine was not running; the Dockerfile itself was not exercised in this Windows verification.

External application implementations and comparative review materials remain outside this project. `analysis/` and temporary review directories are absent. The final 3:53 demo is included under `docs/demo/`, with its recording script in `docs/DEMO_SCRIPT.md`, and is publicly viewable at https://pranay207.github.io/Truecell/demo/. The organizer's real submission destination is not stored in this repository.
