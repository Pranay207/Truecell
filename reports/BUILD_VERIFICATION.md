# Build verification — Truecell Studio 1.0

Executed locally on Windows with 64-bit Python 3.11.9. Core implementation milestone: `7f8fb1f`. Direct pins and the resolved local environment are in `requirements.txt` / `requirements-lock.txt`. The bundled English recognizer's SHA-256 matches its upstream asset and is checked before inference.

- **114 tests passed** in the development environment and **114 passed** in a separately installed clean environment. `pip check` reported no broken requirements. After adding the Python/OS checkpoint fingerprint, the 20 evidence/review/resume tests passed again. Ruff lint and format checks passed for all 43 Python files.
- Tests cover native extraction, opaque-header financial errors, borderless and hierarchical headers, sparse/missing cells, multiple tables, duplicate retention, cross-page split records, invalid inputs, the 50-page guard, failed-page continuation, OCR geometry, typed Excel/formula safety, optional provider schemas, offline defaults, checkpoint mismatch/corruption, source-file tampering, immutable baselines, header/data corrections, history integrity and review invalidation.
- Streamlit AppTest executed the real source inspector and equation-proposal preview. The bank preview changed two failed equation checks to zero in a copy while the working source value remained `1081.00`. Upload/result rendering also passed with duplicate headers and ragged rows. The local Studio server returned HTTP 200 from `/_stcore/health`. No browser surface was available for actual browser screenshot/interaction QA.
- `START_TRUECELL.cmd --check --offline` succeeded. It verified the environment and bundled model without installation. The CLI was exercised in the clean environment on digital and mixed documents; a release-extraction smoke check is described below. System OCR is optional.
- **13/13 strict development cases passed**, including degraded blur/noise (previously 82.64%, now exact), skew, perspective photo, 12 columns and the 50-page/800-row stress document. Both deliberately injected bank-source errors were detected. See `ACCURACY_REPORT.md` for each case, method and measured timings.
- **4/4 scan cases passed with Tesseract excluded** in the clean environment: scanned inventory, blur/noise, 5-degree skew and perspective photo. This selected only the bundled RapidOCR route; it was not an OS-level network isolation or cross-platform test. The photo took about 96 seconds for two pages in this run. `PORTABLE_OCR.json` preserves metrics and timing; reproduce with `python scripts/portable_ocr_check.py`.
- The public layout audit passed its disclosed scope: 35/35 fuel-table data cells and seven headers; 48/48 selected census cells, all 16 headers and both 32-row table shapes; no invented W3C table. Other 464 census cells were not independently checked. Author-provided truth for the three published external dummy PDFs also matched all cells, headers and shapes. These documents informed fixes; neither audit is blind or a relative engine ranking.
- The actual validator's invoice Challenge lab detected **14/24** sampled numeric perturbations with opaque headers; misses remain in `VALIDATION_CHALLENGE.json`. This measures validation sensitivity, not OCR accuracy. Numeric columns without a discovered equation can be unprotected.
- Original sample/public pages were rendered using PyMuPDF because Poppler was unavailable. Native bank, skewed-scan and perspective-photo source boxes were visually checked against original page crops. Approximate Pillow workbook previews were inspected, including Verification and Repair Proposals. openpyxl checks confirmed ten sheets for the bank export, header/data evidence links, retained wrong balance, Unreviewed status and absence of source formulas. These checks are not native Excel rendering or recalculation tests.

The release archive passed ZIP CRC validation and every member matched the workspace source bytes. It contains 137 files, including all 13 sample PDFs and 13 converted workbooks, and excludes local environments, temporary fixtures, credentials and saved/uploaded jobs. After extraction to a separate folder, the clean-environment Python executed the packaged CLI on the three-page invoice and bank document successfully. The bank workbook retained `1081.00`, ten sheets, evidence links and Unreviewed status; its JSON retained the two-equation `1064.00` proposal and correct source hash. Both extracted exports contained no source formulas.

All 13 dummy PDFs include intended JSON/Excel truth and converted Excel/JSON evidence pairs. Converted workbooks preserve source errors and start Unreviewed; arithmetic proposals are not applied to benchmark data. Source and history hashes provide change detection, not identity authentication or accuracy certification. Timings include concurrent local activity; peak memory was not benchmarked.

Not verified here: live vision API behavior, execution on macOS/Linux or Python 3.10/3.12 (CI configuration is supplied, not a claimed CI result), hidden-document accuracy, native Excel rendering, and a recorded demo video. `docs/DEMO_SCRIPT.md` is a recording script. The organizer's real submission destination is still needed.
