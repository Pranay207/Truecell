# Truecell 11-point implementation status

Updated 22 October 2026. This status is based on the current source, regression tests and versioned verification scripts in this repository.

“Implemented” means the behavior exists in the product and has focused regression coverage. It does not mean that every possible document can be extracted with 100% accuracy. Truecell is designed to surface uncertainty, retain source evidence and require review when a result is ambiguous.

| # | Requested capability | Status | What is implemented | Evidence and boundary |
|---:|---|---|---|---|
| 1 | Universal document intake | **Implemented for the declared input contract** | PDF, scanned PDF, PNG, JPG/JPEG, TIFF, BMP and WebP; PDF limit of 200 pages, image/TIFF limit of 50 frames and upload limit of 50 MB; Unicode-native documents and configurable local OCR languages. | `truecell/router.py`, `truecell/api.py`, `tests/test_inputs_recovery.py` and `tests/test_api.py`. Accepting a format is separate from extracting every layout correctly. A 200-page limit is an intake capability, not a 200-page accuracy claim. |
| 2 | Automatic page analysis | **Implemented** | Each page records native-text health, digital/scan/hybrid/damaged/empty mode, image and ink coverage, blur, contrast, skew, rotation, perspective risk, table likelihood/count, document cues, detected scripts, requested OCR languages, risks and the recommended route. | `truecell/profiling.py`, Page Audit records in `truecell/export.py`, and `tests/test_page_profiling.py`. Profiling is a routing signal; it is not a correctness score. |
| 3 | Multiple extraction engines | **Implemented with explicit optional-engine boundaries** | Native PDF line/text/word strategies, bundled checksum-verified RapidOCR and installed local Tesseract produce independently scored candidates. Safe independent candidates can run in bounded two-worker batches; selection remains deterministic and every candidate, rank and selection reason is audited. A validated adapter interface exists for optional layout engines. | `truecell/ocr.py`, `truecell/pipeline.py`, `truecell/models.py`, `tests/test_ocr.py` and `tests/test_page_profiling.py`. PaddleOCR is reported honestly as unavailable until its runtime and a local Truecell adapter are registered; models are never downloaded silently. |
| 4 | Advanced table reconstruction | **Implemented conservatively** | Multi-line and two-to-four-level merged headers, wide tables, wrapped cells, empty columns, repeated headers, split rows, tables continuing across pages, multiple tables, explicitly ruled vertical spans, horizontal body merges and hierarchical group rows are retained with provenance. | `truecell/table.py`, `truecell/ocr.py`, `truecell/layout.py`, `truecell/anchors.py`, `truecell/stitch.py`, `tests/test_tables.py`, `tests/test_ocr.py` and `tests/test_borderless_recovery.py`. Ambiguous unruled vertical inheritance is left blank and queued for review; arbitrary nested or irregular multi-axis layouts are not silently guessed. |
| 5 | Semantic understanding | **Implemented as evidence-based inference** | Header and recurring-value signals infer phone, date, ID, amount, quantity, total, balance and text roles. English, Hindi and Telugu header signals and Unicode round trips are covered. Damaged headers can use repeated-page consensus when source evidence supports it. | `truecell/semantics.py`, `truecell/anchors.py`, `tests/test_semantics_validation.py` and `tests/test_multilingual_evidence.py`. Semantics drive warnings and validation; they do not rewrite source values or promise unrestricted language understanding. |
| 6 | Strong validation | **Implemented** | Shape/header checks, required and high-risk values, semantic type mismatches, shifted columns, sequence gaps, duplicate retention, page/join/provenance continuity, date and number consistency, totals, products and running balances. Formula-injection protection and identifier preservation are included. | `truecell/validate.py`, `truecell/constraints.py`, `tests/test_validation.py`, `tests/test_semantics_validation.py`, `tests/test_baseline.py` and `tests/test_export_edge_cases.py`. Inferred arithmetic is reported as evidence and proposals; it is never auto-applied. |
| 7 | Evidence for every cell | **Implemented for every displayed extracted cell** | A deterministic evidence ID links each header/data cell to original page records, bounding boxes when available, engine, original reading, alternatives, confidence meaning and correction history. Non-empty cells without exact boxes are explicitly marked page-only/unlocated; empty cells are marked not applicable. The same evidence appears through the API, UI and workbook. | `truecell/review.py`, `truecell/api.py`, `truecell/export.py`, `frontend/src/App.tsx`, `tests/test_evidence_review.py` and `tests/test_multilingual_evidence.py`. OCR confidence is labelled as an engine recognition score, never as measured accuracy. |
| 8 | Honest result states | **Implemented** | Job lifecycle states are ready, queued, processing, complete, partial and failed. Quality states are needs review, needs rescan and reviewed. Page failures remain visible, an empty result cannot become reviewed, and failed reasons are retained. | `truecell/api.py`, `truecell/workspace.py`, `truecell/review.py`, `tests/test_workspace_qa.py`, `tests/test_inputs_recovery.py` and `tests/test_evidence_review.py`. A partial job can preserve usable completed pages without presenting the whole document as successful. |
| 9 | Exception-only human review | **Implemented** | A complete paginated queue combines validation findings, low-confidence readings and unlocated evidence. Review decisions are per item, source-attested and bound to an exact result fingerprint. Edits require a reason, preserve original readings and append correction history. | `truecell/review.py`, review endpoints in `truecell/api.py`, the review UI in `frontend/src/App.tsx`, `tests/test_evidence_review.py` and `tests/test_api.py`. Reviewed Excel remains blocked until all current exceptions are checked and the current snapshot is attested. |
| 10 | Reliable delivery | **Implemented and locally verified** | Source launchers, Windows portable build, Docker Compose/server, atomic local workspaces, immutable baselines, source-bound checkpoints, page-level continuation/retry, crash recovery and Excel, CSV, JSON and API delivery. | The final local gate rebuilt and smoke-tested Docker plus the Windows package, including actual OCR and restart persistence. ZIP hash and measured sizes are in `reports/BUILD_VERIFICATION.md`; GitHub CI repeats source/container gates after push. |
| 11 | Real external evaluation | **Evaluation system implemented; independent result pending** | A two-stage blind workflow freezes manifest/source hashes and the extractor source fingerprint, extracts while truth is withheld, emits version-2 run metadata, and requires the evaluator's separately recorded SHA-256 seal to score the saved run. Per-case runtime signatures bind extraction options, OCR packages/models, Tesseract version, requested installed language assets and source. Scoring validates the frozen audit plus workbook `Data N` cells, types and formats without rerunning extraction. | `eval/benchmark.py`, `scripts/blind_benchmark.py`, `eval/blind_manifest.example.json`, `tests/test_blind_benchmark.py` and `docs/BLIND_EVALUATION.md`. A genuine external result still requires an independent evaluator to supply unseen authorized documents and withheld truth. Repository fixtures and public development regressions cannot satisfy that proof step. |

## Overall audit decision

- **Points 1–10:** the engineering paths are present and covered by focused regression tests, with the stated boundaries.
- **Point 11:** the tamper-evident evaluation workflow is ready, but an independent blind run is external work and is not represented as completed evidence.
- **Universal 100% extraction:** not a defensible claim. Finite tests can establish behavior on tested cases; they cannot prove correctness for every document, language, scan condition or layout.

The detailed evidence map is in [`reports/FINAL_11_POINT_AUDIT.md`](../reports/FINAL_11_POINT_AUDIT.md). The final local repository, recorded-output, frontend, container and portable gates passed on 22 October 2026. Independent truth-withheld evaluation for point 11 remains evaluator-controlled.
